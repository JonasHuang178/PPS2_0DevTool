# Proposal

## Why

Merge Request 表格一次取回最多 100 筆，而使用者要從中挑**一筆**交給 AI 分析。目前沒有任何
縮小範圍的手段：只能用眼睛掃。實務上多數時候他要的是「某個人的」或「不是 WIP 的」那幾筆。

另外兩件小事也在同一個畫面上：表格裡每一筆都有 GitLab 網址（取得清單那一步**早就回傳了
`web_url`**，Qt 端從來沒接），而 Repository 清單的每一項都能組出 repo 主頁的網址。兩者目前
都要使用者自己開瀏覽器貼網址。

這四件事落在同一個 tab、同一條資料流上，而且全部屬於「讓使用者選擇」—— 一起做比分三次做
省事，也不會讓畫面改三次版。

## What Changes

**兩個過濾器，都在已經取回的資料上運作**

- **作者過濾**：可勾選清單，項目自該次取回的資料推導（`名稱 (筆數)`），可複選，全不選即顯示
  全部。勾選即時生效。
- **標題排除過濾**：三個輸入欄位（開頭／結尾／包含），各自以逗號分隔多筆關鍵字，命中即不顯示。
  打完（Enter 或移開焦點）才套用，與既有的來源路徑欄位同一個慣例。
- 兩者的預設值與生效時機不同，但都 MUST NOT 觸發重新取得 —— 它們不是查詢條件。
- **新增三個設定鍵**（`Function` 底下本功能區塊）：`Skip_Title_StartsWith_List`、
  `Skip_Title_EndsWith_List`、`Skip_Title_Contains_List`，三者皆選填。

**一個可摺疊的 `Filter` 群組**

- 預設收合，展開後才顯示兩個過濾器的控件。
- **過濾狀態留在摺疊之外**，收合時照樣看得見：取回幾筆、顯示幾筆、各被哪個過濾器篩掉幾筆，
  以及取回筆數是否達到上限。
- 單一 `Clear Filter` 一次清掉兩個過濾器。

**兩個雙擊開啟外部頁面**

- Merge Request 表格的**標題欄**以超連結樣式呈現（顏色與底線、滑過變手形游標），連按兩下開啟
  該筆的 GitLab 頁面。網址取自取得清單那一步已經回傳的 `web_url`。
- Repository 清單的項目連按兩下開啟該專案的 GitLab 主頁，網址由伺服器位址與專案路徑組成。

不做（本輪明確排除）：

- **不把作者送給 GitLab 當查詢參數。** 送出去的話取回的是「某人的前 100 筆」，更精確；但使用者
  得知道自己的 username（表格顯示的是顯示名稱），而「打錯 username」與「這個人真的沒有 MR」在
  畫面上完全一樣。從取回的資料推導則只能挑存在的人，挑不到的那種失敗不會發生。
- **不支援標題排除的萬用字元或正規表示法。** 關鍵字一律為字面文字 —— 既有規格對另一個功能的
  過濾已經明文規定 `*`、`?` 視為一般字元，同一支程式兩個輸入框語意相反會是長期的困惑來源。
- **不記住使用者改過的過濾條件。** 設定檔只提供預設值，重新啟動回到預設。本工具目前沒有任何
  UI 狀態持久化，來源路徑甚至是明文規定不得寫入設定檔的。
- **不讓標題欄單擊即開。** 單擊必須保留給「選取這一列」—— 那是按下 `AI Analysis` 的前提。
- **不改動任何腳本、信封或產物結構。** 四項全部在 Qt 端完成。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `ai-analysis-gitlab-mr`: 畫面新增可摺疊的 `Filter` 群組；新增作者與標題排除兩個顯示過濾器
  與其狀態呈現；Merge Request 表格的標題欄與 Repository 清單新增連按兩下開啟外部頁面的行為；
  釐清顯示過濾器不屬於「查詢條件」因此不觸發清單失效。

## Impact

**Qt（需重新建置）**

- `pps2_0devtool.ui` —— `Merge Requests` 群組內新增 `Filter` 群組（摺疊鈕、狀態標籤、作者清單、
  三個排除欄位、`Clear Filter`）
- `AIAnalysisGitLabMR.h` —— widgets struct 新增上述元件；新增過濾用的 proxy model 子類別
- `AIAnalysisGitLabMR.cpp` —— 作者清單的推導與重建、三個欄位的解析、過濾判定、狀態行的計算、
  兩處雙擊的處理、標題欄的樣式與游標
- `PPS2_0DevTool.example.json` —— `Function` 底下本功能區塊新增三個設定鍵

**腳本**

- 無。取得清單那一步回傳的 `author` 與 `web_url` 都已經存在，這次只是開始使用它們。

**文件**

- `README.md` —— 功能畫面、兩個過濾器的語意與解析規則、三個新設定鍵、兩處雙擊

**相容性**

- 三個設定鍵皆選填；既有部署的設定檔不會長出新鍵，因此排除過濾預設為空 —— 什麼都不藏，與現在
  的行為相同。
- 作者過濾預設為「全不選」，等同顯示全部。
- 信封、腳本參數、產物結構與其版本號皆不變動，持續整合那條路徑完全不受影響。
