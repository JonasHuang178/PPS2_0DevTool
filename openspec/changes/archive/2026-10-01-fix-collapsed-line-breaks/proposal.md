# Proposal

## Why

報告裡有兩處「應該是多行」的內容，轉譯成 markdown 之後擠成一行：

**一、程式碼審閱那一段的日期／作者／連結。** 規格寫的是「附件的日期／作者／連結**三行**」，
而實作寫出的是三行連著的引言：

```
>日期: 2026-09-10
>作者: Jonas
>連結: [CodeReview_x.md](...)
```

段落**內**的換行在 markdown 裡是軟換行，轉譯後變成一個空白 —— 三行於是併成一段。以實際的
轉譯器驗過：

```html
<blockquote><p>日期: 2026-09-10 作者: Jonas 連結: <a ...>CodeReview_x.md</a></p></blockquote>
```

**二、末尾出處的兩行。** 同一個毛病：`Script: …` 與 `Gitlab Pipeline …` 之間只有一個換行，
轉譯後併成同一段。規格說「第二行依環境而定」，而它根本沒有成為第二行。

兩處都不是版面偏好的問題 —— 規格已經規定了行數，實作沒有做到。

## What Changes

- 程式碼審閱的三行改成引言**裡的清單項目**。
- 出處的兩行之間空一行，成為兩個段落。
- **修改兩條需求**，把「幾行」改成對**轉譯結果**的要求：那幾行在轉譯後 SHALL 仍是分開的，
  MUST NOT 依賴段落內的換行。

不做：

- **不用「行尾兩個空白」。** 那是 markdown 的硬換行寫法，但它是**看不見的** —— 編輯器、
  linter 與貼上動作都會把它清掉，而這一段的正確性就靠那兩個空白。專案別處也已經明講
  不留行尾空白。
- **不改每一筆發現底下理由的排版。** 那一處的併段是**刻意的**（既有註解寫明：GitLab 併進
  同一段、結果視窗則如實顯示兩行），不是這次的毛病。

## Capabilities

### Modified Capabilities

- `ai-analysis-gitlab-mr`: 「報告中程式碼審閱那一段的版面」與「最終報告的組成」各加一條
  對轉譯結果的規定。

## Impact

**規格**

- `openspec/specs/ai-analysis-gitlab-mr/spec.md` —— 修改兩條需求

**腳本**

- `scripts/ai_analysis_gitlab_mr/__init__.py` —— 兩處渲染

**Qt**

- 無。結果視窗是純文字、不轉譯 markdown，兩種寫法在那裡都是分行的。

**相容性**

- 只有報告的文字改變，結構與版本號不動。既有產物重跑步驟 5 就會得到修好的版面。
