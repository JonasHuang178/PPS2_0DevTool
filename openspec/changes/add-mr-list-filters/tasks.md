# Tasks

四項需求全部在 Qt 端，沒有任何腳本改動，所以**沒有可以從命令列驗證的部分** —— 驗證一律是
「編得過」加上「在畫面上看到」。這份清單因此把「編譯」與「實機觀察」分開列，前者在任何有 Qt
的環境都能做，後者需要一台能連到 GitLab 的 Windows。

> 本專案的容器沒有 Qt 建置工具，編譯驗證要在 Qt Creator（Windows）或另一台裝有 Qt5 + qmake
> 的機器上進行。

## 1. 畫面骨架

- [ ] 1.1 在 `pps2_0devtool.ui` 的 `Merge Requests` 群組內、`Merge Request Parameter` 之後新增
      `Filter` 群組，內含摺疊鈕、狀態標籤、作者候選清單、三個排除欄位（開頭／結尾／包含）與
      `Clear Filter`；驗證方式為 Qt Designer 開啟後版面無重疊、且表格仍佔據剩餘高度
- [ ] 1.2 `AIAnalysisGitLabMR.h` 的 widgets struct 新增上述元件，`UI_SetupSignal()` 內填入並
      交給功能；驗證方式為編譯通過且零警告
- [ ] 1.3 接上摺疊鈕：切換時改變箭頭方向並顯示／隱藏內容容器，預設收合；驗證方式為執行後點擊
      鈕可展開收合，且**狀態標籤在收合時仍然可見**（規格的關鍵條件）
- [ ] 1.4 在 `README.md` 的功能畫面示意圖中加入 `Filter` 群組；驗證方式為圖與實際版面一致

## 3. 過濾機制

- [ ] 3.1 以 `QSortFilterProxyModel` 子類別承載兩個過濾條件，於 `filterAcceptsRow()` 中先判定
      作者、再判定標題排除（AND）；驗證方式為編譯通過，且兩個條件同時設定時只剩同時滿足的列
- [ ] 3.2 每次取得清單成功後，自**來源模型**掃出不重複的作者與其筆數並重建候選清單；驗證方式
      為取回的資料中有三位作者時，候選恰為那三位且筆數與表格相符
- [ ] 3.3 核對候選不從過濾後的結果推導：勾選一位作者之後，其餘作者的候選項目與筆數不變
- [ ] 3.4 核對候選不受標題排除影響：以排除關鍵字藏掉某位作者的全部 Merge Request，該作者仍在
      候選中且筆數不變
- [ ] 3.5 每次取得清單時清空已選取的作者；驗證方式為選取一位後重新整理，沒有任何作者處於選取
      狀態
- [ ] 3.6 實作關鍵字解析：逗號分隔、每筆去頭尾空白、**空的關鍵字一律忽略**；驗證方式為填入
      `skip,` 與 `skip,,test` 兩種輸入，表格都不會變成空的
- [ ] 3.7 三個欄位以「輸入結束」而非「每個字元」套用；驗證方式為輸入過程中表格不變，按下 Enter
      或移開焦點後才改變
- [ ] 3.8 核對三種比對各自正確、區分大小寫、且 `*` 與 `?` 視為一般字元
- [ ] 3.9 任一過濾條件改變時清空表格選取；驗證方式為選取一筆後勾選作者或修改關鍵字，選取消失
      且 `AI Analysis` 變為停用
- [ ] 3.10 核對改動過濾條件**不會**清空表格、也不啟動任何腳本（表格維持「已取得」狀態）
- [ ] 3.11 `Clear Filter` 一次清掉作者選取與三個欄位；驗證方式為按下後表格顯示該次取回的全部資料
- [ ] 3.12 `README.md` 新增兩個過濾器的語意與解析規則（含關鍵字不可含逗號這條限制）

## 6. 整合驗證（需 Windows 實機 + 可連線的 GitLab）

- [ ] 6.1 `qmake && make` 編譯通過且**零警告**
- [ ] 6.2 **樣式表風險的實測**：選取某一列之後，標題欄是否仍為連結色。外殼的
      `QTableView::item:selected { color: #042C53; }` 可能蓋掉模型的前景色（見 design 的
      Risks）。若被蓋掉，在樣式表中為標題欄補一條規則，並重新驗證
- [ ] 6.3 一次完整操作：選 repository → 取得清單 → 展開 Filter → 勾兩位作者 → 填排除關鍵字 →
      收合 → 確認狀態行正確 → 選一筆 → 按下 `AI Analysis`，流程照常跑完且分析的是畫面上選取
      的那一筆
- [ ] 6.4 摺疊造成的高度變化：展開與收合時表格列數改變，而版面沒有元件被壓到重疊或裁切
- [ ] 6.5 既有行為未退步：切換 repository 與改動查詢條件仍然清空表格並回到「尚未取得」；兩種
      取得方式互斥仍然正確；手動輸入編號模式下表格停用、Filter 群組的狀態不影響該模式
