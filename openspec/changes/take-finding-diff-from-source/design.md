# Design

## Context

動機見 proposal.md 的 Why。這裡只記下讓需求落地時不會被「順手簡化」掉的幾個取捨。

實作已完成並合併（`88359a6`）：AI 的回覆只回位置，程式碼由功能的共用契約自差異中切出。
本次是把那個決定寫進規格 —— 它目前只活在一支 device 鉤子的註解裡，而鉤子是可以被整支
換掉的東西。

既有的分工限制了可選的做法：差異由入口腳本在呼叫鉤子之前取得（既有需求「AI 分析的素材
備置」），而要 AI 回什麼、怎麼解析屬於 device 的鉤子（既有需求「prompt 的組成」）。所以
「程式碼從哪裡來」這件事必須寫在不會被 device 換掉的那一層，而「位置長什麼樣」必須留在
鉤子那一層。

## Goals / Non-Goals

**Goals:**

- 讓「報告裡的程式碼與 Merge Request 上的一致」成為規格層的保證，而不是某支鉤子的實作細節
- 讓定位失敗是看得見的，而不是安靜地少一段

**Non-Goals:**

- 不規定位置標示的形式。那會讓換一種標示法變成改規格
- 不追求定位的命中率。命中率是 prompt 的事，由該 device 自己調
- 不處理「差異被截斷之後，被截掉那部分的位置必然對不上」。那與既有的截斷記號是同一件事

## Decisions

**一、位置用差異中既有的區段標示，不用行號。**

模型照抄一行它看得見的文字，比要它數出行號可靠得多。行號還有一個額外的問題：差異一旦
觸及大小上限被截斷，行號的意義就與呼叫端手上的內容對不起來，而那正是最需要它對得上的
時候。被否決的替代方案是「檔案 + 起訖行號」，它在模型端與呼叫端都多一次換算。

**二、標示的比對放寬，但解析不跨檔。**

模型可能只回那一行、可能連行尾附帶的脈絡一起回、可能把整段連內容一起貼回來、也可能在
外面多包一層圍籬 —— 四種都指向同一個位置，只認其中一種會讓另外三種變成「對不上」，而
那個訊息指不到真正的原因（它其實指對了）。

放寬的是**怎麼認出標示**，不是**到哪裡去找**。解析限於該筆發現所屬的檔案：同一個標示在
不同檔案中各自存在是常態，跨檔取用會把另一個檔案的程式碼放進這一筆發現，而每一步都回報
成功。這一條與 device 解析鏈「種類只在自身 device 之內」是同一種判斷 —— 寬容要用在認人
上，不能用在找東西上。

**三、對不上時不回退、不失敗，記一筆。**

三個選項都考慮過：

| 做法 | 否決理由 |
|---|---|
| 回退成用回覆中的程式碼 | 把這次要避免的事安靜地放回來。既然看不出發生過，也就不會被修 |
| 讓那一步失敗 | 一筆對不上的引用毀掉一份已經付費完成的分析，代價與收益不成比例 |
| **不附程式碼、留紀錄** | **採用。** 標題與理由本身仍有價值，而紀錄讓命中率是可觀察的 |

紀錄要指出是哪一筆（哪個檔案的哪個位置），不能只說「有幾筆對不上」—— 調 prompt 的人需要
的是能拿去跟回覆比對的那一個值。

**四、切片的能力放在功能的共用契約，不放 `script_utils`，也不讓各 device 自己寫。**

它只服務這一個功能，所以不屬於跨功能的技術領域分組；但每一個採用這條需求的 device 都
需要它，所以也不該各寫一份 —— 各寫一份就是每個 device 各有一套「什麼算同一個位置」的
規則，然後各自漂移。放在功能的共用契約與 `fence_for()`、`finding()` 同一層，是既有的
device 公開 API 該去的地方。

**五、產物的結構不變，版本號不動。**

發現所附的程式碼仍是一個字串欄位，只是它的來源變了。結構沒變就不該改版本號 —— 改了會讓
既有的中間產物莫名其妙地失效，而本專案明確支援「拿昨天的產物單獨重跑渲染那一步」。

## Risks / Trade-offs

**模型照抄標示的準度未知。** → 命中率由上面的診斷紀錄觀察。對不上的後果是少一段程式碼，
不是失敗，所以準度不足時的退化是漸進的而不是斷崖式的。真的偏低時該調的是該 device 的
prompt，不是放寬解析。

**既有自訂 device 的鉤子不會自動符合。** → 規格管得到「報告裡的程式碼該從哪裡來」，但
一支自行其是的鉤子仍可能把回覆中的內容直接當成產物。這是需求落地的範圍問題，不是破壞性
變更；新增 device 時照範本走即可。

**位置標示的形式沒有寫進規格。** → 代價是「規格保證程式碼取自差異，但沒保證怎麼指位置」。
這是刻意的：形式屬於鉤子，寫進規格會讓換一種標示法變成改規格。風險由決策二的寬鬆比對
吸收。

## Migration Plan

無。實作已完成並合併，產物結構與設定檔都沒有變動，既有部署不需要任何動作。
