這個功能在做什麼

從一個目錄挑出 .cpp，把選擇存成一份設定

📁
來源目錄
某一層底下的
.cpp 檔案。
→
📝
暫存設定檔
你挑中的那幾個，
每行一個絕對路徑。

設定檔放在作業系統的暫存目錄，檔名由 scripts/single_building/__init__.py 的 SETTING_FILE_NAME 決定一次（目前 PPS2_0DevTool_single_building.txt），三支讀寫它的腳本共用那一個宣告。

開跑之前

什麼都不用設

# 不需要憑證、不需要 config、不需要環境變數。 # 只要 Python 3，連 requests 都用不到（那是給連 GitLab 的功能用的）。 cd scripts

這是它與 AI Analysis 最大的差別 —— 那一條要 GitLab、JIRA 與 AI 三組憑證， 這一條完全不連網，只碰本機的檔案系統。

四支各自做什麼

每一支：吃什麼 → 做什麼 → 吐什麼

四支都不需要 config。要給的只有 source_path 與（寫入那一支的）params。

掃
列出來源目錄裡的 .cpp
..._list_source.py　action: list_source
不連線
吃什麼
source_path
是目錄，不是檔案
做什麼
列出那一層的 .cpp。 不遞迴，副檔名比對不分大小寫。
吐什麼
data.files
每筆有 name 與 path
四支裡只有這一支用得到 source_path。 另外三支讀寫的是暫存設定檔，與來源路徑無關。
讀
讀出已保存的設定
..._list_target.py　action: list_target
不連線
吃什麼
什麼都不用給
做什麼
讀暫存設定檔，每行一個絕對路徑。
吐什麼
data.files
形狀與 list_source 相同
檔案不存在或內容為空不是錯誤，是「設定為空」—— 回成功、空清單。
寫
寫入設定
..._modify_setting.py　action: modify_setting
不連線
吃什麼
params.files
絕對路徑的清單
做什麼
整份覆寫暫存設定檔。不是附加。
吐什麼
data.count
寫進去幾筆

..._recovery_setting.py　action: recovery_setting
不連線
吃什麼
什麼都不用給

不必記上面那些

--dump-config 會把信封模板印給你

python3 single_building/single_building_modify_setting.py --dump-config
{ "_template_version": "2.0.0", "action": "modify_setting", "source_path": "", "config": {}, "params": { "files": [] }, "_help": { "config": {}, "params": { "files": "要保存的絕對路徑清單，一個字串一筆" } } }

填完存成檔案，用 --request 餵進去即可。模板由參數宣告導出， 不是另外手寫的一份 —— 所以它不會與 --help 或實際接受的鍵不一致。

一個會讓你以為壞掉的地方

排序由 Qt 做，不是腳本

命令列拿到的次序與畫面上不一樣
list_source 回的是 os.listdir() 給的次序 —— 腳本裡沒有任何 sorted()，所以那個次序不保證，會隨檔案系統而異。 上面的範例輸出剛好是 a10.cpp 在前。
畫面上看到的自然排序（a2.cpp 在 a10.cpp 之前）在 Qt 的代理模型裡。 命令列使用者要同樣的次序得自己排。
這是刻意的：排序是呈現，而腳本不負責呈現。

常見問題

在命令列上最常被問的

要先裝什麼？
只要 Python 3。連 requests 都用不到 —— 這四支完全不連網。
設定檔到底在哪裡？
作業系統的暫存目錄（Windows 上是 %TEMP%）。 每一支的回應 detail 都會印出完整路徑，不必自己猜。
可以挑 .cpp 以外的副檔名嗎？
不能從命令列改 —— 它是功能專屬的定義，寫在 scripts/single_building/__init__.py 的 SOURCE_SUFFIX。
modify_setting 是附加還是覆寫？
整份覆寫。要保留舊的就先 list_target 讀出來，自己合併之後再一起寫回去。
會遞迴掃子目錄嗎？
不會，只掃那一層。這是刻意的 —— 遞迴時一棵大樹會回來幾千筆。
命令列改了設定，工具裡看得到嗎？
看得到 —— 兩邊讀寫的是同一個檔案。 但工具不會自己重讀，要切走再切回那個分頁才會重新載入。
四支都不連網、不要憑證。
list_source 的 path 直接餵給 modify_setting 的 files。
